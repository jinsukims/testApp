==============================================================
 할 일 앱 GitHub 업로드 명령어 (실행한 순서대로)
 저장소: https://github.com/jinsukims/todo-app
==============================================================

[1단계] 상태 확인 - 읽기만 하고 아무것도 바꾸지 않음
--------------------------------------------------------------

1. git status --short --branch
   → 커밋하지 않은 파일과 현재 브랜치 확인

2. git remote -v
   → 연결된 원격 저장소 확인 (pythonExample에 연결되어 있었음)

3. gh auth status
   → GitHub CLI 로그인 상태 확인 (jinsukims 계정)

4. gh repo view jinsukims/pythonExample --json name,visibility,defaultBranchRef,isEmpty,description
   → 기존 저장소 정보 조회 (공개 저장소, 비어 있지 않음)

5. gh api repos/jinsukims/pythonExample/contents --jq '.[] | .type + "  " + .name'
   → 기존 저장소의 파일 목록 조회 (함수.pptx 하나)

6. gh api repos/jinsukims/pythonExample/commits --jq '.[0:3][] | .commit.author.date + "  " + .commit.message'
   → 기존 저장소의 최근 커밋 조회 (2019년)

7. git ls-remote origin
   → 원격 저장소의 브랜치와 커밋 해시 조회

8. gh repo view jinsukims/todo-app --json name
   → 새 저장소 이름이 비어 있는지 확인 (없음 = 사용 가능)

9. git config user.name
   git config user.email
   → 커밋 작성자 정보가 설정되어 있는지 확인


[2단계] 파일 준비와 커밋
--------------------------------------------------------------

10. .gitignore 파일 만들기 (편집기로 작성, 아래 내용)
    ----------------------------------------
    # Claude Code 대화 내보내기
    2026-*-command-*.txt

    # 화면 캡처
    캡쳐*.png

    # 비어 있는 중첩 git 저장소
    Todos/
    ----------------------------------------
    → 여기에 적은 파일은 GitHub에 올라가지 않음

11. git add index.html style.css app.js README.md CLAUDE.md .gitignore
    → 올릴 파일 6개만 골라 스테이징

12. git status --short
    → 스테이징된 파일이 6개인지 확인 (A = 새로 추가)

13. git branch -M main
    → 브랜치 이름을 master에서 main으로 변경

14. git commit -F - <<'EOF'
    할 일 관리 앱 초기 버전

    순수 HTML/CSS/Vanilla JS 할 일 관리 앱.
    - 추가·수정·삭제·완료 체크, localStorage 저장
    - 카테고리 배지, 키워드 기반 자동 카테고리 분류
    - 진행률, 카테고리·상태 필터, 정렬, 완료 항목 일괄 삭제
    - 저장 오류 처리, 반응형(360~1280px), 키보드 접근성

    Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
    EOF
    → 여러 줄 메시지로 첫 커밋 생성 (결과: 771d4aa)
    → 한 줄 메시지라면: git commit -m "할 일 관리 앱 초기 버전"

15. git log --oneline -1
    → 방금 만든 커밋 확인


[3단계] 새 저장소 만들기와 업로드
--------------------------------------------------------------

16. git remote remove origin
    → 기존 pythonExample 연결 끊기 (GitHub의 pythonExample은 그대로)

17. gh repo create jinsukims/todo-app --public --source=. --remote=origin --push --description "Vanilla JS 할 일 관리 앱"
    → 공개 저장소 생성 + origin으로 연결 + 업로드를 한 번에 처리
       --public       공개 저장소
       --source=.     현재 폴더를 저장소 내용으로 사용
       --remote=origin  origin이라는 이름으로 연결
       --push         만든 뒤 바로 업로드
       --description  저장소 설명

    ※ gh 없이 git만 쓸 경우 (GitHub 웹에서 저장소를 먼저 만든 뒤)
       git remote add origin https://github.com/jinsukims/todo-app.git
       git push -u origin main


[4단계] 결과 확인
--------------------------------------------------------------

18. gh repo view jinsukims/todo-app --json url,visibility,defaultBranchRef --jq '.url + "  " + .visibility + "  " + .defaultBranchRef.name'
    → 저장소 주소, 공개 여부(PUBLIC), 기본 브랜치(main) 확인

19. git rev-parse HEAD
    git ls-remote origin main
    → 로컬 커밋과 GitHub 커밋의 해시가 같은지 비교 (둘 다 771d4aa...)

20. gh api repos/jinsukims/todo-app/contents --jq '.[].name'
    → GitHub에 올라간 파일 목록 확인 (6개)

21. gh api repos/jinsukims/pythonExample/commits --jq '.[0].sha[0:7] + " " + .[0].commit.author.date'
    → 기존 저장소가 바뀌지 않았는지 확인 (2019년 커밋 그대로)


==============================================================
 앞으로 코드를 고친 뒤 올릴 때
==============================================================

git status                         # 바뀐 파일 확인
git add 파일이름                    # 올릴 파일 고르기
git commit -m "변경 내용 설명"       # 커밋 만들기
git push                           # GitHub에 업로드
